# Decision record — SDK migrations and Catalog V1 scope

Date: 2026-10-26
Main: `main` (PR #204 merged); follow-up code review: PR #205 on `cleanup/sdk-migration-and-debt`; documentation reconciliation: `docs/reconcile-migration-state-2026-10-26`
Status: active implementation decision; SDK migration not yet closed

## Objective

Complete the remaining migrations to Wix's recommended SDKs and remove demonstrably obsolete code/debt with narrow, testable changes. Avoid broad refactors and do not merge or publish until critical regression checks pass.

## Wix Stores Catalog

**Keep Catalog V1 temporarily.** Migration to Catalog V3 is explicitly deferred and excluded from the current work. Do not introduce Catalog V3 calls, inventory schema changes, V3 webhooks, or dual-version runtime detection as part of this phase.

This decision supersedes the earlier Wix-plan recommendation to prioritize Catalog V3 for the current sprint. That recommendation remains a future backlog item, not an implementation instruction.

## Migration order

1. eCommerce Checkout V1 to Cart V2 (@wix/ecom), including a package-version/lockfile reconciliation generated by the package manager.
2. Remaining Bookings imports/calls from legacy namespaces to @wix/bookings, verifying method and payload contracts.
3. Member identity lookups from wix-members-backend to @wix/members.
4. Confirm CMS operations use @wix/data and centralized permission elevation; confirm secrets use @wix/secrets.
5. Search for residual legacy imports, obsolete dependencies and stale test mocks. Remove only when no production or test consumer remains.
6. Run focused contract tests, full backend regression, lint/type/build checks, then Wix Preview and critical booking/payment/sync tests.

## Definition of complete

100% migrated requires a source and dependency inventory with no unexplained legacy production imports, correct SDK method contracts, regenerated lockfile where packages change, passing relevant tests, and successful preview validation. A grep-only result or a successful compile is insufficient.

## Safety gates

- Keep the existing booking model: simple booking and dual F1/F2 with exposure gap.
- Preserve staff/resource identity, permissions, idempotency, payment compensation and post-payment synchronization.
- Do not weaken fiscal, ledger, or security assertions to make tests green.
- Keep Catalog V1 unchanged during this phase.
- Do not merge or publish production changes until CI and Wix Preview blockers are resolved.
